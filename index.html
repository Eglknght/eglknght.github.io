Inventory Management System

A web app for tracking stock in and out, managing products and categories, and reading reports, with separate access for admins and employees.

What it does

Sign in by role
Passport.js with bcrypt-hashed passwords and session login. Admins see every menu. Employees see the dashboard, stock in/out, and reports.
Products and categories
Add products with a code, description, and category. Categories are managed separately.
Stock in and stock out
Pick several products in one form with search-as-you-type, set a quantity for each, and save. Stock out is checked against what is available, and every movement is written to the stock history.
Dashboard
Summary cards for total products, total categories, and low-stock items, plus a doughnut chart of stock per category.
Reports
View all products or one product, and filter by date range. The filters stay in the URL, so a filtered report can be shared.
Safe logout
Logging out destroys the session and clears the cookie. A no-cache header stops the back button from reopening the dashboard.

From MySQL to PostgreSQL

The app started on MySQL. When I moved it to a hosting plan that provides PostgreSQL, I migrated it instead of changing hosts.

What changed: the connection pool now uses pg, table definitions use SERIAL keys, and inserts list their columns explicitly. The user table became users, because user is a reserved word in PostgreSQL. Counts are cast to integers so the dashboard receives numbers, not strings.

Deployment: hosted on TokenKoding Vibe Deploy with a managed PostgreSQL database. Tables are created on first start, and the first admin account is created from environment variables.

Run it locally

  1. Clone the repository and run npm install.
  2. Create a PostgreSQL database and put its connection string in .env as DATABASE_URL.
  3. Set SESSION_SECRET. Optionally set ADMIN_USERNAME and ADMIN_PASSWORD to create the first admin.
  4. Run node app.js. The tables are created automatically on first start.
